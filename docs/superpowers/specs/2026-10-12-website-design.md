# cc-hub 官网设计

日期：2026-10-12
仓库：`Jenwein/cc-hub`（公开）
地址：https://jenwein.github.io/cc-hub/ （GitHub Pages，暂不用自己的域名）

标注约定：没有标注的内容是用户的决定；标"（Claude 定）"的是 Claude 替用户做的选择，用户可以改；标"（留给实现者）"的由实现者决定。

---

## 1. 这是什么，为什么做

cc-hub 刚开源。官网给想用 cc-hub 搭自己 agent 工作区的开发者看，目的是让他们看完去安装。

官网由两部分组成：一个宣传性质的首页，和一个文档站。文档站取代仓库里现有的用户文档，成为唯一的一份。

## 2. 目标、非目标、绝对不能出的错

**目标**

- 开发者打开首页，几秒内明白 cc-hub 是什么、在整条链路里管哪一段，并且能直接复制安装命令。
- 文档站讲清安装、配置、概念、应用和全部命令，读完能自己搭起来。
- 中英双语，英文为主。

**非目标**

- 自己的域名（以后可以加）。
- 访问统计或任何收集访客数据的东西（Claude 定）。
- 多版本文档：只有一套，对应最新发布的版本（Claude 定）。
- 首页的命令行录屏或动画（Claude 定：这一版不做）。
- 图形 logo（Claude 定：先用等宽字体的 "cc-hub" 文字标识）。
- 实时从 GitHub 拉应用列表（Claude 定：首页应用区手工维护）。

**绝对不能出的错**

1. 网站说的和 cc-hub 实际行为不一致。网站文档是唯一的一份用户文档，随代码一起改、一起发布。
2. 首页或文档里的安装命令、命令示例跑不通。
3. 死链接（站内链接，以及从 README、CLI 提示指向网站的链接）。
4. 宣传 cc-hub 做不到的事。cc-hub 只是工作区这一层：聊天和调度属于 cc-connect，运行时和权限属于 agent。

## 3. 首页

风格：暗色、极简、命令行感，参考 Bun 和 uv 的首页（用户从三种方向里选的 A）。

从上到下六块：

1. **首屏**：顶部导航（文档、应用、GitHub 带星数、语言切换）；大标题；一句说明；安装命令 `uv tool install cc-hub`，带一键复制；"看文档"按钮。
2. **它在哪一环**：一条横向示意图，"你的聊天机器人 → cc-connect → cc-hub"，每段一行说明，cc-hub 那段高亮。
3. **总站里有什么**：六个格子，分别是记忆、人格和用户信息、skills、定时任务、应用、"数据归你、有版本、升级不碰你的文件"（同时点出 agent 无关：Claude Code、Codex 都能用）。
4. **三步上手**：安装 → `cc-hub init` → 把 cc-connect 的 `work_dir` 指向总站，发第一条消息；每步链到对应文档。
5. **应用**：推荐卡片，`hub-apps` 里的 ledger（已发布）；一格"写你自己的应用"，链到文档和 GitHub 上的 `cc-hub-tap` topic。尚未发布的应用（例如 dreams）只在发布后才加卡片（Claude 定）。
6. **页脚**：再放一次安装命令；文档、GitHub、MIT 许可。

文案（Claude 定的初稿，实现者可以润色，但要保持意思和语气）：

- 标题：The home directory for your chat-driven coding agent.
- 说明：Persona, memory, skills and scheduled tasks for Claude Code or Codex behind cc-connect.
- 中文：标题和说明由实现者翻译，语气同样简洁直接。

## 4. 文档站

左侧目录：

- **开始**：安装和升级；快速上手（从安装到发出第一条消息）；配置 cc-connect。
- **概念**：总站和其中每个文件的作用；记忆怎么记、怎么整理；skills 和定时任务；agent 首次运行时的适配（`hub-adapt`）；总站是一个 git 仓库。
- **应用**：安装和使用应用；写自己的应用；发布一个 tap。
- **指南**：备份总站；Windows 说明；遇到问题怎么反馈。
- **参考**：每条 `cc-hub` 命令的用法。

写法：

- 内容来自现有的 `docs/install.md`、`docs/cc-connect.md`、`docs/apps.md`、`docs/backup.md`、`docs/windows.md`、README 和设计规格（`docs/superpowers/specs/2026-09-22-cc-hub-design.md`），整理成上面的结构。"概念"和"参考"是新写的，事实以代码和设计规格为准。
- 只描述当前的设计，不写演变过程，也不写"我们为什么不做某事"。
- 命令都写全，带 `cc-hub` 前缀，第一次出现时说明 `<>` 和 `[]` 的意思，并给出真实的例子。
- cc-connect 本身的安装、聊天机器人的创建都不写，链到 cc-connect 自己的文档；"配置 cc-connect"一页只讲怎么把它指向总站（`work_dir`、环境变量），这是 cc-hub 这一层的事（Claude 定，依据项目只管工作区这一层的原则）。
- 首页安装命令下方有一行小字："需要 uv 和 git"，链到安装页（Claude 定）。
- 文档站有搜索、暗色模式。

## 5. 语言

- 英文是原文，路径在根目录；中文是对照翻译，在 `/zh-cn/` 下。首页和文档都有两种语言。
- 哪页还没有中文，就显示英文原文，并提示"本页尚未翻译"。
- 首次发布时，首页和"开始"部分必须有中文；其余页面的中文可以随后补（Claude 定）。

## 6. 技术和发布

- 源码放在 cc-hub 仓库的 `site/` 目录（Claude 定）。
- 用 Astro + Starlight 搭（Claude 定）：文档站用 Starlight 自带的目录、搜索、暗色模式和多语言；首页是自定义页面，按 §3 实现。
- 构建需要 Node，只在 CI 和本地预览时用，不进 cc-hub 的 Python 包，也不影响 `uv tool install cc-hub`。
- 网站对应最新发布的版本，不跟 `main` 走（Claude 定）：文档改动和代码改动在同一个拉取请求里合进 `main`，但等打了版本标签才上线，这样网站说的永远是 PyPI 上那个版本的行为。安装页里的版本号从最新标签取，不手写。
- GitHub Actions：
  - 打 `v*` 版本标签时构建并发布到 GitHub Pages；另有一个手动触发，用于只改文档、不改代码的修正（Claude 定）；
  - `main` 上的提交和拉取请求只构建和检查（链接检查、两种语言都能构建），不发布。
- 中文译文过期提醒（Claude 定）：每个中文页面记下它所翻译的英文页面的内容指纹；英文页改了而中文页没跟上时，CI 给出警告，但不让构建失败。
- GitHub 上的星数在构建时取一次，取不到就不显示数字（留给实现者）。

## 7. 现有文档的迁移

- `docs/install.md`、`docs/cc-connect.md`、`docs/apps.md`、`docs/backup.md`、`docs/windows.md` 的内容搬进网站后，从仓库里删掉。
- 开发用的文档留在仓库：`docs/acceptance.md`、`docs/superpowers/` 下的设计和计划。
- `README.md` 和 `README.zh-CN.md` 精简为：一句话说明、快速上手、链到网站对应页面的文档列表。
- cc-hub 命令输出里提到文档的地方改成网站地址：`doctor` 关于备份的提示（现为 `docs/backup.md`），`init` 关于 cc-connect 环境变量的提示（现为 `docs/cc-connect.md`）。
- `pyproject.toml` 的项目链接加上主页和文档地址；GitHub 仓库的简介和主页栏填上网站地址。
- 设计规格里提到 `docs/*.md` 的地方，改为指向网站的对应页面。
- `CHANGELOG.md` 记在下一个补丁版本（0.4.1）下。CLI 提示的改动只有发布新版本后才到用户手里，所以这项工作以发布 0.4.1 收尾；发布前先问用户（Claude 定）。网站首次上线就跟着 0.4.1 的标签。

## 8. 验收

- CI 里构建通过，两种语言都构建出来。
- 站内链接检查全部通过；README、CLI 提示里指向网站的链接都能打开。
- 首页的安装命令和"三步上手"的前两步，加上 `cc-hub doctor`，在一台只装了 uv 和 git 的干净 Linux 环境（例如容器）里照做能跑通；第三步的配置写法对照 cc-connect 的文档核对。接上真实聊天机器人的完整流程属于 `docs/acceptance.md` 的人工验收，不在这项工作里（Claude 定）。
- 手机宽度下首页和文档都能正常阅读。
