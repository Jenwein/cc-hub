# cc-hub 0.7.0 Reports Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the reports mechanism: daily/weekly/monthly/quarterly/yearly reports that installed apps add sections to, that tasks leave notes for, which cc-hub assembles, sends through `cc-connect send`, and archives.

**Architecture:** Each period is a hub scheduled task `cron/report-<period>.md` (`default: false`), turned on and retimed with the existing `cc-hub cron set`. Apps declare sections in `apps/<app>/reports/<period>.md`: a frontmatter `command` makes a script section (cc-hub runs the approved command and pastes its stdout), no command makes an instruction section (the agent writes it and hands it over with `cc-hub report put`). `cc-hub report send` assembles everything, calls `cc-connect send`, writes `reports/<YYYY>/<date>-<period>.md` and commits it; the agent never sees script output. Per-machine state (approvals, notes, drafts, run times) lives under `.cc-hub/reports/`; user settings (language, order, sections turned off) live in `hub.toml`'s `[report]` tables, edited in place.

**Tech Stack:** Python ≥ 3.11, typer, rich, tomli-w, pytest, ruff (existing stack, no new dependencies).

**Spec:** `docs/superpowers/specs/2026-10-16-reports-design.md`. Read it first; the main design is `docs/superpowers/specs/2026-09-22-cc-hub-design.md`, and `docs/superpowers/specs/2026-10-12-cron-overrides-design.md` covers time overrides.

## Global Constraints

- Every `.py` file starts with `# -*- coding: utf-8 -*-`; text IO goes through `cc_hub.encoding.read_text` / `write_text`.
- Commands that change the hub commit only their own paths via `gitops.commit_paths`; messages start with `cc-hub: `; a failed commit is a warning (`console.warn`), never an error. Errors go to stderr with exit 1 (`console.fail`).
- Changes to `hub.toml` are in-place text edits of one table that keep every other byte (CRLF included), as `cronoverrides` does today; an edit that would not parse back to the intended data is refused.
- Periods, exactly: `daily`, `weekly`, `monthly`, `quarterly`, `yearly`. Report task names: `report-<period>`.
- Default schedules, exactly: daily `0 8 * * *`, weekly `0 20 * * 0`, monthly `0 9 1 * *`, quarterly `10 9 1 1,4,7,10 *`, yearly `20 9 1 1 *`; all `default: false`, `session: new_per_run`.
- Every registration command cc-hub builds ends with ` --silent`.
- cc-hub runs only script-section commands the user approved on this machine, and calls cc-connect only to send a report. Nothing else changes in cc-hub's "never executes app strings" and "never calls cc-connect" rules.
- `cc-hub report send` never prints report content; script output must not reach stdout/stderr of any `cc-hub` command.
- Built-in report wording exists in English and Chinese; a `language` starting with `zh` uses Chinese, anything else (or unset) English.
- `AGENTS.md` ≤ 150 lines; each `skills/*/SKILL.md` ≤ 100 lines; `BOOTSTRAP.md` keeps exactly 5 numbered steps (existing tests).
- No test needs a real cc-connect: the sender and the command runner are injectable.
- Version becomes `0.7.0`; tagging and publishing are out of scope (the user approves the release).

## Review Focus

1. Script output in Chinese on Windows (console code page not UTF-8) → the section text arrives intact: run commands with `PYTHONUTF8=1` and decode stdout as UTF-8 with `errors="replace"`. Test in Task 4 (`test_command_output_is_utf8`).
2. cc-connect missing from PATH, not running, or exiting non-zero → `report send` exits 1 with cc-connect's message; notes and drafts are kept, nothing is archived, the run is not recorded as sent, so a retry works. Test in Task 5 (`test_send_failure_keeps_everything`).
3. A task runs `report note` while `report send` is assembling → the new note is neither lost nor sent twice: both take `apps.hub_lock`, and `send` drops only the notes it included. Test in Task 5 (`test_note_added_after_assembly_stays`).
4. A section command that hangs or floods output → killed after `SECTION_TIMEOUT` (300 s), replaced by the failure line; output over `MAX_SECTION_CHARS` (20000) is cut with a marker. Tests in Task 4.
5. `hub.toml` from a Windows clone (CRLF, comments, a hand-written `[report] order`) → `report language` / `report section` change only their table and keep line endings. Test in Task 2 (`test_report_tables_edit_in_place_with_crlf`).

**Interfaces:**
- Produces: `class TableEditError(ValueError)`; `header_path(line: str) -> tuple[str, ...] | None` (parses `[a]`, `[a.b]`, `[a."x/y"]`, with spaces and a trailing comment; None for anything else, including `[[array]]`); `edit_table(text: str, path: tuple[str, ...], values: dict | None) -> str`.
- `edit_table` semantics: the table whose header parses to exactly `path` gets exactly `values` as its own keys (written with `tomli_w`, in the dict's order); keys whose values are tables (child tables such as `[report."a/daily"]` under `[report]`) are kept. `None` removes the header and its own keys (only allowed when it has no child tables in the file; otherwise `TableEditError`). A missing table is appended at the end, separated by one blank line, in the file's line ending. Raises `TableEditError("not valid TOML: …")` for unparsable input and `TableEditError("cannot edit in place")` when the result does not parse to: the old data with that table's own keys replaced by `values` (or the table removed), everything else equal.

  - `@dataclass class ReportConfig: language: str | None; order: list[str]; off: set[str]` (`off` holds keys `<app>/<period>` whose table says `enabled = false`).
  - `load_config(hub: Path) -> ReportConfig` — reads `[report]`: `language` (string matching `LANGUAGE_RULE`), `order` (list of strings), and child tables `"<app>/<period>"` holding only `enabled` (bool). Anything else → `ReportError` naming the key, e.g. `hub.toml: [report] order must be a list of app names`.
  - `ordered(sections: list[Section], order: list[str]) -> list[Section]` — apps named in `order` first, in that order, then the rest by app name.
  - `enabled_sections(hub: Path, period: str) -> list[Section]` — sections of `period` without an error and not in `off`, ordered.
  - `periods_on(hub: Path) -> dict[str, bool]` — from `crontasks.rows`: row `report-<period>` exists, has no error and `enabled` is true.
  - `note_target(hub: Path, period: str) -> str | None` — the first period at or after `period` in `PERIODS` order that `periods_on` says is on; None when none is.
  - `save_language(hub: Path, tag: str) -> None`, `save_section(hub: Path, key: str, on: bool) -> None` — in-place edits of `[report]` (keeping `order` and any other existing own key) and `[report."<key>"]` (`on=True` removes the table, `on=False` writes `enabled = false`); read bytes and keep CRLF as `cronoverrides.save` does.
  - `section_keys_of(hub: Path, app: str) -> list[str]` — keys `<app>/<period>` present in `[report]` (for removal).

### Task 5: Sending, archiving and routing notes

**Files:**
- Modify: `src/cc_hub/reportbuild.py`

**Interfaces:**
- Produces:
  - `Sender = Callable[[str], None]`; `cc_connect_sender(*, which=shutil.which, run=subprocess.run, env=os.environ) -> Sender` — runs `[<cc-connect path>, "send", *(-p CC_PROJECT if set), *(-s CC_SESSION_KEY if set), "--stdin"]` with the text on stdin (UTF-8), timeout 60 s; raises `ReportError` with `"cc-connect not found on PATH"`, `"cc-connect send failed (exit N): <stderr or stdout>"` or a timeout message. | Command | Behaviour |
|---|---|
| `report list [--json]` | JSON `{"language", "periods": [{"period", "task", "schedule", "on"}], "sections": [{"app", "period", "kind", "title", "command", "file", "on", "approved", "error"}]}`; text: one line per period, then one per section. |
| `report plan <period> [--json]` | `reportbuild.plan(...)`; text mode prints a short summary. Unknown period → exit 1 `unknown period <x>; use daily, weekly, monthly, quarterly or yearly`. |
| `report put <period> <app> [--text TEXT]` | Stores a draft (from `--text`, else stdin). Refused (exit 1) unless `<app>/<period>` is an enabled instruction section. |
| `report send <period> [--again]` | Prints exactly one of `sent: <n> section(s), <m> note(s)`, `nothing to send`, `already sent today; --again sends it once more`; a commit warning goes to stderr; `ReportError` → exit 1. Never prints report text. |
| `report note <period> --from <source> <text>` | Exit 0 with `kept for the <target> report`; when no report is on, exit 3 with `not kept: no report is on; reply with it yourself`. |
| `report section <app> <period> --on\|--off` | Exactly one flag. `--off` needs the section to exist; `--on` also clears a leftover table. Writes `hub.toml`, commits `cc-hub: report section <app>/<period>`, prints the new state. |
| `report language <tag>` | Validates `LANGUAGE_RULE`, writes `[report] language`, commits `cc-hub: report language`. |
| `report approve <app>` | Records every command section of the installed app (period → command), prints each `approved: <period>: <command>`; an app without command sections prints `nothing to approve`. |

All errors: `ReportError`, `apps.AppError`, `LockError`, `OSError`, `UnicodeDecodeError` → `console.fail`.
