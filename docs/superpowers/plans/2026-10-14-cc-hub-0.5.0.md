# cc-hub 0.5.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship cc-hub 0.5.0: user-overridable task times, pointer registration, script / on-demand / restricted tasks, a PreToolUse guard for restricted tasks, and the credential exception in `AGENTS.md`.

**Architecture:** Task definitions are parsed by a new `crontasks` module that also builds the registration rows; overrides live in `hub.toml` and are edited in place by `cronoverrides`; the guard hook is `cronguard`; a new `cc-hub cron` command group exposes `list / set / reset / wake / guard / guard-setup`. cc-hub still never registers anything in cc-connect itself: it prints the commands, the agent runs them. The only cc-hub → cc-connect calls are `cron wake` (list + exec).

**Tech Stack:** Python ≥ 3.11, typer, rich, tomli-w, pytest, ruff (existing stack, no new dependencies).

**Spec:** `docs/superpowers/specs/2026-10-12-cron-overrides-design.md` and `docs/superpowers/specs/2026-10-14-script-tasks-design.md`. Read both before starting; the main design is `docs/superpowers/specs/2026-09-22-cc-hub-design.md`.

## Global Constraints

- Every `.py` file starts with `# -*- coding: utf-8 -*-` (enforced by `tests/unit/test_docs.py`).
- Text IO goes through `cc_hub.encoding.read_text` / `write_text` (UTF-8, LF, atomic replace).
- Commands that change the hub commit only their own paths via `gitops.commit_paths`, messages start with `cc-hub: `; a failed commit is a warning, never an error.
- Errors go to stderr with exit 1 (`console.fail`); query commands support `--json` (`console.echo_json`).
- Task names: hub tasks use the file name without `.md`; app tasks use `<app>/<task>`; both match the app name rule (`^[a-z0-9][a-z0-9-]{0,63}$` per part). Registration description is `hub:<name>`.
- Schedules are five-field cron expressions.
- Pointer prompt, exact: `Scheduled task hub:<name>: follow the body of <file> in the hub.` where `<file>` is `cron/<name>.md` or `apps/<app>/cron/<task>.md`.
- Script task default `timeout_mins` is 10; on-demand placeholder schedule is `0 0 1 1 *` (registered then disabled).
- `AGENTS.md` stays ≤ 150 lines.
- Tests run on Linux and Windows CI (`.github/workflows/ci.yml`); no test may need a real cc-connect.

## Review Focus

1. A hand-edited `hub.toml` (comments, blank lines, CRLF from a Windows clone, a `[cron]` table written with dotted keys) → `cron set`/`reset` change only the one task's section or refuse with a clear message; they never rewrite the whole file. Tests in Task 2.
2. `cc-hub update` on a hub that already has `[cron."…"]` overrides → the file keeps its comments and overrides byte-for-byte except `template_version`. Test in Task 2.
3. The guard runs on every tool call of every session: a normal chat session, an unreadable or missing transcript, a hub with a broken task file, or a cwd outside any hub → no output, exit 0, never a traceback. Tests in Task 6.
4. A hub path with spaces and non-ASCII characters (`中文 hub`) → guard path checks and `cron set` work. Tests in Tasks 2 and 6.
5. `cc-connect cron list` lines whose descriptions share a prefix (`hub:mail/triage` and `hub:mail/triage-old`), or a task registered twice → `wake` matches exactly and refuses duplicates. Tests in Task 5.
